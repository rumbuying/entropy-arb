# Bulk 固定数量止损与独立看护

本阶段补齐普通网格的保护执行基础，候选只在隔离环境验证，未安装到生产 worker，也没有新增资金授权。当前生产仍为只读接入。固定数量止损不等于 Hyperliquid 的原生全仓止损。

## 执行和数量语义

BulkWireRules 只编译向下触发、无指定执行限价、全仓资金域中的固定数量卖出止损。请求必须 reduce_only=true、whole_position=false、GTC，价格字段等于触发价，数量和价格满足原生精度及最低额；不借小额探针规则放宽普通网格。共用日志独立存储 fixed_quantity 元数据，逐项核对幂等参数。BulkKeychain 继续使用既有、独立验证的 V4 签名字节及六字段 stop root 哈希。

订单经共用 AccountExecutor 分配 CID，Bulk 日志在签名前绑定原 nonce、root ID 和公开准备字节。UNKNOWN 只查原单；不会凭等了几秒换一个身份再挂单。协议 stop 本身只能减仓，不在普通 limit 订单上推断同等语义。此前有限 stop-only 工具仍保持其更窄的白名单；通用订单通道增加 stop 格式不扩大旧探针授权。

固定止损有独立 BulkProtectionManager，接入共用 ProtectionManager 的配置检查、准备和核验入口。保护上限覆盖仓位、已挂买单以及准备/在途买单，不把未成交卖单当可用保护额度。共用日志与 Bulk 原请求日志在同一个 SQLite 事务读取，等待原生快照期间任何经济状态变化都使本次观察作废。

替换时先确认新止损在原生条件簿中且容量足够，然后才撤旧止损。过渡中两个已知止损分别校验身份、触发价和数量，容量只取选定的新止损，不能把多个不足的止损相加。新单或旧撤单结果未知都沿用原身份；撤销中的止损不能授权新开仓。暂停及一般撤单保留固定止损，确认平仓后的清理可以显式撤销。

## 每笔新增风险的最终检查

发送前重新取得完整原生账户，核对实际仓位、原生挂单、选定止损及全部潜在买入数量。墙钟和单调时钟都限制本次观察不超过5秒，不能靠墙钟停顿使用过期快照。网络和策略检查等待结束后，再次核对账户状态、策略 epoch、共用引擎权限、私有流、公共风险输入及独立看护健康情况。减仓退出、撤单不新增公共风险或保护完整性前提。

账户归零后仍需重新查询实际止损；保留在数据库中的历史成功或指针不能授权再次入场。原生止损已消失时阻止新增风险，不假设固定 stop 永久跨越归零，也不自动忽略触发子执行。

## 持久保护证明与看护

成功的完整原生查询在同一写事务中重新校验经济状态，保存精确数量、订单身份、配置和 epoch。证明有效期为30秒，墙钟和单调时钟任一先到期即失效；进程会话也必须一致。该期限是本地证明有效期，不是延长订单寿命或资金授权。

独立看护不依赖被阻塞的原生查询。到期后在本地提升 epoch、禁止新开仓并持久排队退出，即使前一个请求卡住或不响应取消，也不能阻塞该决策或用晚到回执续期。实际平仓仍须经原执行器、原订单终态、成交/资金费与仓位对账证明；排队退出不等于已经清仓。

短暂查询失败或正在回补仓位时，若原数量证明仍有效，可以等待，期间不能取得新开仓许可；失效后请求退出。独立看护自身不健康时也会在本地请求退出，不等待下一次网络查询。明确止损缺失、容量不足、出现反向仓位等危险不被“仓位还在对账”掩盖。重启不复用旧进程证明，启动前可先持久记录退出任务，无需等待网络。即使账户适配器或凭证尚未加载，也能从已保存的固定止损元数据识别该要求；加载失败不能跳过看护。

断线进入恢复 epoch 时，只能携带未过期且仍能覆盖全部潜在买入数量的同一份证明，原时间和期限不变；保留既有挂单还要求独立看护健康。这不是带仓恢复已通过的证明。恢复对账、触发子执行和新的实际证明仍需独立验收。

## 证据与未完成范围

- 本机广回归及 Linux 冻结回归覆盖实际 Runtime/SQLite/AccountExecutor、原生格式离线协议和 HL 共用保护回归。最终 Linux **742项通过、0失败/错误/跳过**（155.55秒，1个既有aiohttp warning）；源码和 XML 摘要以 `data/run/grid-bulk-fixed-manager-linux-v6.json/xml` 为准，不把此前 v1/v2/v3 的计数相加。
- `grid-bulk-fixed-manager-sdk-v2.json` 在 Linux 固定 SDK 中使用已知未入金临时密钥，36组与两个官方 Rust oracle 比对，实际签名及发送格式/篡改拒绝通过。socket connect 被禁止，没有用户账户或密钥访问；这不是主网挂单或止损触发测试。其三个 SDK 相关源码摘要须与最终候选逐一相同。
- 所有场景中的新金融发送均为离线测试替身，不是主网交易。生产数据库、旧套利及正在观察的 HL 服务不变。

完整 Bulk 上线仍缺初始/范围风险模型、IP 共享优先限流、完整历史覆盖与触发根单/子执行映射、归零时止损取消后的完整自动重挂流程、小残仓及退出端到端、网站完整生命周期、真实网格补单/带仓故障和至少24小时观察与独立终局。当前拒绝 Bulk 的 service_coverage 重挂窗口配置；不能把本地证明看护等同该重挂资格，或把排队退出当真实清仓。
