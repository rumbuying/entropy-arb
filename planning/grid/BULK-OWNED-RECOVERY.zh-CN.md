# Bulk：账户起始点与自有范围恢复

目标是让正常网格在断线后按真实自有订单、库存和费用恢复。保留交易所全局历史 `unknown`，不要求先证明与当前网格无关的全部旧历史，也不把新范围证明冒充全局覆盖。

## 已接入的起始点（v41）

`BulkAccountVenue.capture_recovery_baseline(market_ref)` 在账户执行锁内只建立一次基线，调用前后核对同一账户：所有市场零仓零单、保证金已结清、原金融请求已有闭合证据、核心无活动网格或未决操作。查询期间原请求、订单绑定、nonce 或核心状态变化时不提交。

基线保存余额、fees/funding/realizedPnl 等原生累计值、全账户原请求身份边界、历史页原生 slot 锚点及快照时间。记录与审计事件原子提交；重复调用和重启返回同一记录。不同币种共享账户起点、使用各自带市场作用域的游标。凭证轮换不重置经济起点。

`BulkGridVenue.history_cursor_from_snapshot` 已接引擎创建流程的既有钩子；它检查账户、部署、凭证与时间。只读预览保留原拒绝行为，执行资格入口缺少起点时拒绝。该游标仅代表起始边界，不更新 `coverage:*` / `funding:*`，也不授予恢复或资金权限。

旧撤单沿用用户明确给出的清理政策，不再强迫已确认取消的旧止损给出从未提供的成交累计量；这只允许以当前真实空账户建立新经济起点，不证明旧明细完整。原启动检查已抽成共用闭合验证，原诊断入口的整 worker 空核心限制不变；基线单独按经济账户隔离，不因其他独立账户在运行而拒绝。

## 已接入的批量与 OPEN 入账（v42）

共享的两次挂单簿观察确实来自不同网络请求，同一 history 分页仅该轮复用；64 个混合原单与成交为7次读。每个原单仍过原语义解析，Unknown/遗漏/异常分页不制造终态。显式条件模式保留在挂根单累计未知，以单列的未触发观察依据证明当次没有执行；自然止损同OID真成交读取已实际主网验证。小于潜在覆盖上限的正面FILLED实际量可保存，原bound/请求/回执不改。

恢复入账现在对未结束单重新取整组可变快照，与不可变终态一起全序回放；OPEN数量不缓存跨重启，分批终态扫描轮换，旧经济字段变化拒绝。新开仓资格仍未放开。全账户经济证明、current资金费及最终恢复出口仍必须继续。

## 下一步：完整范围证明与恢复出口

1. 以基线指纹为根，快照账户所有市场的核心请求、原生绑定与资金归属。基线后存在未归属的诊断/外部金融请求时拒绝；未发送状态必须有不可复活证明。未知发送继续查询原身份。
2. 全部自有普通单及保护根单都参与。普通单累计量与真实成交精确相等；已成交止损复用已证实同 OID 转为 market/filled 的映射。条件单仍在挂单簿时仅记录“未触发的在挂观察”，不能把累计未知改成查询已知。
3. 长期运行必须有界分批与缓存正面不可变终态。现有 v30/v40 的单次 16 原单及只缓存终态，不能作为完整方案：网格恢复时大量普通单仍 OPEN。应共享同一批原生 openOrders/orderHistory 响应，逐原单精确解释，再以新鲜账户状态夹验，避免每个 CID 都重复读全挂单簿。
4. 按真实成交全序拆分已闭合生命周期和当前生命周期。已闭合继续使用原生数量、峰值、成交量、VWAP、时间及费用匹配。当前仓位使用原生 size/price/fees/funding/realizedPnl，与基线后自有生命周期及当前账本匹配，不能套用不存在的 openTime/maxQuantity。
5. 同一账户全部市场一起核对：自有库存等于原生仓位；原生挂单均有原绑定；逐笔成交费用与原生生命周期费用一致；closed 与 current 的原生资金费/已实现损益变化与账户累计差额一致。逐笔支付与区间净额继续分开记账，防止重复。外部资金变化、未归属仓单、费用/资金费缺项或冲突均保持未决。
6. 保存明确的 account-owned 范围证明，绑定基线、请求集合、核心 epoch、原生观察范围和账本提交位置；提交前再查控制与绑定。先原子入账、再决定恢复，不把旧范围证明用到新增请求或新连接代次。
7. RecoveryBarrier 和资金费同步器使用新的范围证明独立作恢复依据。原全局 HistoryPage/FundingPage 的 complete/truncated 状态、游标均不改。证明失效只冻结新增开仓，原保护与减仓退出继续依其授权执行。

原生取消后未提供 stop 累计量，不能直接给普通运行伪造零成交。若使用全账户库存守恒推导某个已闭合单未执行，必须另有全部普通单正面累计、自有 stop 只减仓、全市场费用及资金变化互证等足够证据，并将推导来源与原查询未知分开保存；不足时不授予恢复。

## 已确认的原生字段

2026-10-31 实际 HTTP fullAccount 返回 `kind/name/authorizedAgentWallets/margin/reserve/positions/openOrders/feeTiers/leverageSettings`。**没有 pendingOnFill 或 lockedAmounts 字段**；不能把 `get(..., [])` 的默认值称作原生“待处理为零”证明。起点基于明确的空仓空单、已闭合原请求和原生结清保证金。

本地已审计官方源码 `data/grid-sdk-sources/bulk-audit-20261025/bulk-client-567dbc51/crates/api-rust/src/msgs/account.rs` 的 PositionInfo 对多个字段使用默认零，甚至不包含实际响应里的 fees/funding。继续使用直接保留数字文本的原始响应，缺少当前费用或资金费时拒绝，不能依赖 SDK 默认值补齐。

真实 v37 账户推送中的当前仓位字段为 size、price、realizedPnl、unrealizedPnl、fees、funding 等，没有 openTime/maxQuantity。原始 470 帧已在 `tests/fixtures/grid_bulk/native-ioc-stop-stream-20261030.json` 保留文本；当前 snapshot 字段只能作为原生证据，推送成交仍须 REST 确认。

完成以上恢复接线后，继续真正普通网格的创建/启动/暂停恢复/结束、maker 双向补单、保护归零重挂、带仓故障、小残仓和有限期 24 小时独立验收。基线本身不代表这些项目通过。
