## 批准后的执行步骤

1. 原账户、凭证 revision、政策范围与源摘要复核。确认普通 Bulk worker 仍只读且无 grid、operation、普通订单意图；Hyperliquid 与套利服务不操作。
2. 只暂时停止独立 Bulk observer，使用现有 vault 和 runtime 的独占锁；其他实例仍持锁则退出。不要把凭证复制到本机或另建 nonce 库。
3. 使用隔离 Linux 诊断环境和已审查源码运行 CLI，普通 GRID_REAL_DISPATCH 保持 0。CLI 自身不控制服务、不后台常驻，不接受替代网站/交易源站。
4. 原始 stop CID、nonce、SDK bytes 与原生 OID 在 HTTP 前持久化。发出后结果未知只查询原身份，不能重发 stop。撤单另有唯一持久 RID/nonce，目标只能是原 stop OID；未知撤单也不重发。
5. 核对原 stop、原 cancel 与终态历史。完整原生账户零仓零单只是当前物理状态；没有原订单历史终态就保留 unknown，不能改成成功或资格通过。原生 stop 触发或非零执行记录不在本工具的终态证明范围内，必须另行核查。
6. 退出前保存服务器私有 SQLite 备份与无密钥结果；正常退出后恢复 Bulk 只读 observer。异常先检查原 PID、原请求、账本和 native 状态；不得因工具超时就另建请求。期限内不能清理或历史不明时明确报告，绝不宣称完全收尾。

本工具没有处理整个 Bulk 上线所需的组合初始保证金、同账户多币种预算、带仓/持续保护、止损触发子执行链接、真实网格循环、断线/重启恢复、残仓与 24 小时验收。以上仍需独立完成。
