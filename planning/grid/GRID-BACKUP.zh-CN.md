# 网格在线备份

更新：2026-10-14。独立网格备份不访问旧套利配置、`.env` 或旧数据库，不发送交易请求，不暂停当前网格。

通过 SQLite 在线备份生成一致运行库，读取成品的完整性与已提交事件序号；加密账户文件及其配套主密钥只作原样本机复制，不解密、不输出内容。启动资格文件可随包保存。备份目录700、文件600，符号链接、不合规权限与网站静态目录拒绝使用。密文或启动政策在备份期间变更则整包拒绝发布并清理临时文件，避免留下看起来完成的半包。

在项目目录执行：

```sh
.venv/bin/python -m entropy_arb.grid.backup --policy data/run/grid-live-release-policy.json --policy data/run/grid-operator-trial-policy.json
```

默认保存到 `data/grid-backups/grid-日期-唯一编号/`，包含运行库与校验清单、`credentials/master.key`、`credentials/accounts.enc`，以及指定的私有启动政策。输出只有路径、完整性与事件序号。此目录在Git忽略范围；不能搬到网页静态目录。当前没有自动上传到其他机器。

恢复必须先使用新隔离目录和禁止新实盘派发的运行时，核对备份之后的原生挂单、成交、资金费及当前仓位。备份之后的交易可能不在包内，不能把旧账本当成当前事实；不能直接覆盖正在使用的库、恢复旧client id计数后继续开新单，或因备份里保存了资格文件而自动重新启用实盘。只有完整恢复核对和身份/资格重新验证后才能部署，原生保护与可恢复的清理路径须保持。

六项验证覆盖：运行库仍在写入/WAL中的已提交事件包含在成品、加密文件对可在独立目录恢复、完整权限、源文件变动失败清理、符号链接/权限拒绝，以及实际静态目录拒绝。均使用临时测试库与测试凭证，没有主网写入。

实际当前网格备份：`data/grid-backups/grid-20261014T010912Z-24c34683`，完整性ok、已提交事件84；发生在第三轮ETH持仓且暂停时，BTC已创建但启动遇到传输异常。它记录该时刻的状态，后续恢复与交易不能据此省略核对。
