## 已实现的控制

- `position_stop_wire` 单独构造整个仓位止损；先验证正数实验上限、币种/账户、精度和 reduce-only，再编码原生零大小。普通 `_wire` 仍拒绝零数量。
- `PositionStopProbe` 只做空仓零敞口验收：签名后重新核对授权、账户和新报价；持久传输记录先于 HTTP；按 CLOID 和原生订单号验证后只撤自己的单。未知回执不能解释为未发送。
- `position_protected_ioc` 先独立查到完整保护，才允许限额 IOC 入场。签名后状态变化、预挂拒绝和入场拒绝均不继续建仓；未建仓时中途重启只清理旧保护。
- PREPARED 的已知未传输入场与 Native 明确拒绝分开记录。未终结操作继续阻止凭证替换，重新启动且额度0仍可完成已有记录的清理。
- 部分成交离线用例验证原生零大小保护不会因父单取消而被本地删除；真实数量归属始终来自原生成交，不从零大小止损推算经济成交。
- 账户页面只展示“小额先挂整个仓位止损、入场和退出通过”，继续标注持续网格待认证，不改变 `live_eligible`。
- REST 观察新增按 API 地址、同一事件循环共享的滚动预算，每分钟保守700权重，分页响应额外计费；429使观察进入60秒冷却。签名动作不自动重试，不将过期签名发送到交易所。此预算不能治理旧套利或其他进程的 IP 流量。

最新全量 **872 passed、2 skipped、108 warnings（58.36秒）**。相关原生保护、限流、账户与网站回归通过；签名字段不出现在公共响应。

## 正式网格接入要求

真实证据说明整个仓位止损可以在空仓时提前挂置，并在本次小额完整建仓后继续存在。**尚未证明两侧保护同时存在、中性方向跨零、仓位增长/真实部分成交后的触发数量、实际止损触发和持续网格循环。** 不用离线覆盖或官方说明替代这些真实证据。

接入正式运行时应继续遵守：

1. 按网格和市场持久化保护身份、触发价、原生限价、保护类型和库存上限；先确认保护在交易所，再派发可能增加仓位的普通网格订单。中性网格必须证明两侧保护可同时存在，不能用单边认证替代。
2. 整个仓位 `s=0` 是订单类型语义，不是经济成交数量。保护成交按真实 fills 绑定本网格库存和 FIFO；触发时先推进 epoch/冻结补单，再处理迟到成交，不能继续相邻价位循环。
3. 普通暂停、风险暂停、断线清理和保留仓位停止只撤风险订单；原生保护持续留在交易所。只有独立证明实际平仓和账本清零后才能撤销保护并释放市场占用。
4. 重启或恢复先核对全部已有保护、持仓、订单和成交；查不清或保护不足时冻结新开仓。不得通过零大小的订单查单结果制造累计成交证明。
5. 正式风险检查要识别保护订单，继续核对所有同账户网格和共享保证金。严格的全 DEX REST 检查每次超过200权重，5秒全量轮询不能长期满足官方配额；需要接入有时效和断线标记的账户 WebSocket 组合证据，保留 REST 恢复兜底。
6. 完成 Native 部分成交、仓位变化、真实触发、断连/重启、尘仓、历史覆盖和完整网页创建/暂停/恢复/停止闭环，之后再生成按网络/账户/市场/凭证/规则版本绑定的正式资格记录。
