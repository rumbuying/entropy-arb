# 网格优化交付记录

日期：2026-10-11。基于现有实现继续修改，保留计算器、严格配置模型和模拟合同基础，修复交易核心并重建网站工作台。**当前已形成可验证的模拟交易和手动管理闭环；真实交易所接入、高级自动化与行情回测仍未全部完成。**

## 本轮完成的功能

### 交易与账本

- 成交必须属于正确账户、市场和本网格订单；支持只带交易所订单号的成交，拒绝外来成交污染库存。成交与资金费都有持久归属，不再把前一网格的历史计入新网格。
- 修复 FIFO 和跨零费用分配；总净收益、已实现、浮盈、手续费、净资金费与配对解释分别展示。资金费使用实际模拟支付，收到为正、支付为负。
- 多头/空头的退出单使用正确的 reduce-only，重新开仓单正常开仓；配置的 GTC 不再被静默改成 post-only。立即建仓实际执行 IOC 后按真实库存挂单。
- 部分成交先积累持久补单需求，达到数量和名义门槛才下单；同一档位已有订单时不会再创建重复物理订单。
- 补单拒绝或结果不明时阻断新增风险，撤销已知挂单并保留资金占用；迟到成交继续记账。

### 生命周期与恢复

- 暂停先更新持久 epoch 和目标模式；在途派发不再被当成未发送订单直接过期。暂停期间的成交不续挂。
- 恢复先检查订单、历史和独立持仓，再按当前价格和存量库存重新挂单，避免只改成“运行中”却没有订单。
- 停止平仓使用有价格保护的 reduce-only IOC；必须同时证明账本仓位、独立账户仓位、外部和内部未决订单均清零，才能 CLOSED 并释放资金/市场占用。保留仓位结束时继续占用市场。
- 暂停或停止可以抢占启动、恢复和热调整；旧异步回调不能把策略重新写回 ACTIVE / RUNNING。
- UNKNOWN、不完整/截断历史、外来挂单和仓位漂移阻断恢复；恢复 checkpoint 只在覆盖证明成立时推进。
- schema 升级至 v6；运行库启动先取得文件排他锁，模拟交易所订单/成交/行情状态独立持久化。实际进程重启先恢复核对再提供 RPC。

### 管理接口与资金

- 修复 RPC 握手、重复操作返回结果、超时后查询原请求状态以及单客户端并发响应绑定；订单返回实际累计成交量。
- 热调整预览绑定目标网格、配置、版本、epoch 与有效期；旧库存保留旧版本退出价格，新订单使用新版本。
- 追加系统资金缓冲、调整投入规模与账户可用资金守卫接通；调整规模会保留额外缓冲，重复请求不重复追加。
- 自动补缓冲的底层执行、额度和触发幂等已修复，但自动条件调度与网页配置尚未形成产品闭环。
- 订单、成交、配对与事件支持分页；网页可导出当前页 CSV。完整一致性导出任务仍待实现。

### 网站界面

- 重建创建、列表和详情为交易工作台：服务端账户/市场选择，多头/中性/空头、等差/等比、投入、杠杆、高级资金与执行配置。
- 开单使用服务端预览与首次订单计划；参数改变立即禁用旧预览，过期后重新校验，防止页面参数与实际提交不同。
- 图表展示服务端价格档位和已观测行情；模拟数据明确标记。未接入真实 K 线时不制造历史数据。
- 详情展示六项收益、仓位、每格数量、资金占用、配置版本，以及订单/成交/配对/事件记录。
- 接通暂停、恢复、结束平仓、结束保仓、调整区间/数量/规模和追加缓冲；操作前展示影响和当前状态，使用稳定请求 ID 与 epoch。
- 页面离线时保留上次数据并禁用操作；路由切换销毁旧轮询与请求，降低过时响应覆盖页面的风险。
- 1280 桌面、390 手机、360 窄屏实测无页面横向溢出。交易表格在自身容器内滚动。

6. **资金语义**：追加缓冲目前是系统预留，不是交易所逐仓划转；每格规模取决于计算器，不能把模拟离散风险表用于真实保证金。
