# 网格与套利模块分离决策

日期：2026-10-11。依据用户最新决定，取代此前跨策略账户硬互斥、统一旧 worker 执行治理的首版要求。

## 产品边界

- 同一网站设置独立的“网格交易”和“套利交易”入口，各自管理账户配置、策略、订单、收益和运行记录。
- 网格独立账户配置/凭证引用不自动继承套利配置；网格密钥管理使用独立加密存储，不读取或回写套利 .env。
- 使用者负责选择不同真实资金账户，并为两套系统配置各自的签名凭证。换 API Key 但仍对应同一资金账户，不构成账户分离。
- 配置位置给出简短提示，不增加跨策略查重、互斥服务、确认弹窗或账户接管流程。

## 执行边界

- 保留独立 GridRuntime、运行库、启动配置和发送出口；旧套利保持自己的执行、签名和运行数据。
- 网格内部保留账户/市场占用、资金预算、持久 nonce、签名锁、epoch 和恢复屏障，同一账户同一市场不同时运行两个网格。
- 套利启动、重启、平仓和诊断不查询网格占用；网格服务不可用不影响套利操作。
- 不为跨策略账户共用提供兼容保证，也不尝试证明或阻断该用法。跨策略互斥与旧 worker 统一治理移出当前开发范围及实盘放行前置条件。
- 真实保证金模型、历史完整性、私有流恢复、实际账户授权及交易所适配器认证仍是网格本身的必要工作。

## 本次落地

- 网站导航分为网格、套利和套利运维组，网格提供独立的列表与创建入口。
- 网格创建页提示使用专用资金账户，不增加确认步骤。
- 删除旧套利平仓预览对网格 claims RPC 的依赖；保留网格内部占用和诊断接口。
- 套利操作回归测试将网格 RPC 设置为不可用，仍验证平仓预览及后续操作正常。
- 更新技术规格、产品方案、执行 AI 交接以及当前接入/状态文档，后续不继续开发跨策略互斥。
